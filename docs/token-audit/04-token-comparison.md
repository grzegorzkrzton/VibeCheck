## Status definitions

| Status | Meaning |
|---|---|
| Match | Name, value (after documented normalize), type tier, and mode behavior align |
| Partial match | Credible counterpart with material differences (aliases, units, storage form, or indirect adapters) |
| Mismatch | Proposed pair but values or families conflict |
| Missing in code | Present/documented in Figma; no coded token |
| Missing in Figma | Present in code; no Figma variable/style in inventory 01 |
| Unclear | Insufficient evidence (e.g. Foundations labels, absent categories on both sides) |

Rules applied: similar values alone ≠ Match; primitives ≠ semantic tokens; uncertainty stated explicitly.

## Dimension checklist (cross-cutting)

### 1. Token names
Most live Figma variables align with `--vc-*` after `/`→kebab, duplicate-segment collapse, and `--vc` prefix (see 03 High rows). Exceptions: Foundations labels (`text/primary`, `action/primary`, …) do not match live names. Badge `pending - bg` maps to `badge-pending-background` via documented shorthand normalize.

### 2. Token values
Primitive HEX and (resolved) semantic Light/Dark HEX align with `tokens.json` for all Colors collection entries checked. Opacity `45` vs `0.45` is not proven. Font family Inter vs system-ui stack conflicts. Shadow alphas align after HEX8↔% normalize.

### 3. Token types
Primitive↔primitive and semantic/component↔semantic/component pairings are respected. No status treats a primitive swatch as a semantic UI token.

### 4. Aliases and references
Figma Colors are `VARIABLE_ALIAS` to Primitives. Code stores resolved HEX in `color.light` / `color.dark` — **Partial match** for those rows. Code `--theme-*` → `var(--vc-*)` is a second alias hop not present in Figma.

### 5. Theme or mode behavior
Figma Colors: Light/Dark. Code: light defaults + `@media (prefers-color-scheme: dark)` in `design-system/generated/tokens.css`, forced `tokens-light.css` / `tokens-dark.css`, and `#vibecheck-layer[data-scheme]` in generated `tokens.js` layer CSS. Primitives/dimensions: Figma `Value` ↔ code shared. Mode **behavior** is present on both sides for colors; exact switching mechanisms differ (Figma modes vs CSS/media/attributes).

### 6. Semantic meaning
Role groups (text, surface, pin, badge, button, …) correspond where live variables exist. Foundations specimen labels use older vocabulary (`action/primary`, `text/primary`) — Unclear vs current semantics.

### 7. Units
Spacing/radius/size: Figma raw floats vs code `Npx` — Match when numbers equal. Opacity units Unclear/Partial. Motion uses `ms` in code only.

### 8. Typography structure
Figma: 5 text styles (family, size, weight, line-height, letter-spacing). Code: only `--vc-font-family` (system stack). Size/weight/line-height/letter-spacing **Missing in code**. Family **Mismatch** (Inter vs system-ui).

### 9. Shadow structure
Pin/Card/Panel: offset, blur, and alpha align → Partial match (effect style vs CSS string). `--vc-shadow-pin-open` Missing in Figma.

### 10. Responsive or breakpoint behavior
No breakpoint tokens in either inventory → Unclear / absent on both sides.
